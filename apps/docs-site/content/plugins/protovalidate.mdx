# Protovalidate

`ProtoRequestValidation` runs [protovalidate](https://github.com/bufbuild/protovalidate) against inbound request messages.
Invalid requests become HTTP 400 responses with Connect-shaped error details.

## Annotate the schema

```protobuf
syntax = "proto3";

package stricteliza.v1;

import "buf/validate/validate.proto";

message SayRequest {
    string sentence = 1 [(buf.validate.field).string.max_len = 100];
}
```

## Install the plugin

```kotlin
embeddedServer(CIO, port = 8080) {
    install(Resources)
    routing {
        install(ContentNegotiation) {
            connectJson()
        }
        install(ProtoRequestValidation)
        strictElizaService(StrictElizaServiceHandler)
    }
}.start(wait = true)
```

`ProtoRequestValidation` returns Connect JSON errors for invalid unary POST requests without a `StatusPages` handler. It also checks Connect GET messages after decoding. An invalid request returns HTTP 400 with `invalid_argument` and violation details.

Install the plugin only on routes that should validate protobuf requests. It handles its validation failure before an application-wide `StatusPages` handler. Existing `StatusPages` handlers can continue to handle errors from other routes; no validation-specific handler is required.
Validation rules stay in the `.proto` file — the server only enforces them.
