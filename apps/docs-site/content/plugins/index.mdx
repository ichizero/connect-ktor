# Plugins

Connect-Ktor is a small set of focused Ktor pieces, not a single framework switch.

Most apps start with [serialization](/plugins/serialization) plus the
[code generator](/code-generator).
The rest are optional guards you turn on when the traffic shape needs them.

| Piece                                   | Role                                                      |
| --------------------------------------- | --------------------------------------------------------- |
| [Serialization](/plugins/serialization) | `connectJson()` / `connectProto()` for ContentNegotiation |
| [Connect GET](/plugins/connect-get)     | Idempotent unary over HTTP GET                            |
| [Body limit](/plugins/body-limit)       | Decoded-size caps (`connectBodyLimit`)                    |
| [Compression](/plugins/compression)     | Gzip with `UnaryCompressionGuard`                         |
| [Protovalidate](/plugins/protovalidate) | Request validation via Buf validate rules                 |

Install only what the route needs.
REST routes outside a Connect scope keep Ktor's default behaviour.

Route interfaces from `.proto` services live under
[Code generator](/code-generator) — that tool is not a Ktor plugin.

For the protocol behaviour each plugin implements (content types, Connect GET,
error codes), see the official [Connect protocol](https://connectrpc.com/docs/protocol)
docs rather than treating these pages as a full protocol reference.
